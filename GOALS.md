# Goals

These are the standing directions `fairdm-docs` works toward. Each one is a capability or
quality to steer by, not a task that gets ticked off. Whether any goal has been served well enough
is decided in the roadmap, the feature specs, and review, never by the goal itself.

This file carries no version numbers or release plan; that lives in the roadmap. For what the
package is, what it stays out of, and the principles that settle a close call, read the
*Scope & philosophy* section of the [README](README.md).

Importance is a tag on each goal, not a ranking:

- **Essential** — not worth adopting without it.
- **Expected** — a complete, dependable version is expected to have it.
- **Aspirational** — a genuine want whose absence never makes the package incomplete.

| ID | Goal | Importance | Status | Notes |
|----|------|------------|--------|-------|
| G1 | A portal builds a complete documentation site with no configuration file of its own in its documentation source | Essential | | |
| G2 | A portal's registered data model is documented from the registry, without anyone describing it a second time | Essential | | |
| G3 | A portal's documentation is published to GitHub Pages from its own continuous integration | Essential | | |
| G4 | The rendered site carries the portal's own name, description and branding rather than the framework's | Essential | | |
| G5 | A portal's brand assets, bibliography and other documentation inputs are found where the package already looks, without wiring | Expected | | |
| G6 | This package's own documentation shows a portal developer how to do the things worth doing well | Expected | | |

_Written 2026-08-26. Revise as the goals change._
